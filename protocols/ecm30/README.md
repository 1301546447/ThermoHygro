## 1. 通信概览

| 项目 | 值 | 依据状态 |

| 协议族 | Modbus RTU，串口 | 既有实现 |

| 默认波特率 | 9600 | 既有实现 |

## 2. 寄存器与指标

| 指标 | 原始寄存器地址 | 功能码 | 寄存器数 | 比例 | 符号 | 单位 | 量程（本实现采用） | 实物验证 |
|---|---|---|---|---|---|---|---|---|
| 温度 | `0x0100` | `0x03` | 1 | ×0.1 | 有符号（补码） | ℃ | −40 ～ 125（**待确认**） | 待验证 |
| 湿度 | `0x0105` | `0x03` | 1 | ×0.1 | 无符号 | %RH | 0 ～ 100（**上限待确认**） | 待验证 |

说明：

- `0x0100`、`0x0105` 是**报文中的原始寄存器地址**，不擅自换算成 4xxxx 文档编号。
- 湿度上限存在 99/100 的说法差异，需实物或厂家资料确认。
- 在确认连续寄存器与副作用之前，**不把两个请求合并成一次范围读取**。
- 温度量程是“本实现的合理性检查范围”，不是已确认的传感器量程。

## 3. 帧格式

### 请求帧（8 字节）

```
[地址] [0x03] [寄存器高] [寄存器低] [数量高] [数量低] [CRC低] [CRC高]
```

### 正常回复帧（7 字节）

```
[地址] [0x03] [字节数=0x02] [数据高] [数据低] [CRC低] [CRC高]
```

CRC 覆盖 CRC 字段之前的全部字节（请求 6 字节、回复 5 字节）。

### 异常回复帧（5 字节）

```
[地址] [功能码|0x80] [异常码] [CRC低] [CRC高]
```

异常码含义：

| 码 | 含义 |
|---|---|
| 0x01 | 非法功能码 |
| 0x02 | 非法数据地址 |
| 0x03 | 非法数据值 |
| 0x04 | 从站设备故障 |
| 0x05 | 确认（处理中） |
| 0x06 | 从站设备忙 |
| 0x08 | 存储奇偶校验错 |
| 0x0A | 网关路径不可用 |
| 0x0B | 网关目标设备无响应 |

> 异常回复**不解析为温湿度值**，按异常码报告。

### 关键风险：回复不含寄存器地址

回复中**不包含请求的寄存器地址**。因此 `01 03 02 00 EB …`（23.5）这样的帧，既可能是温度也可能是湿度。

- 归属只能依靠**可靠的一问一答上下文**；
- 不能用“数值落在正常范围内”来判断归属；
- 超时后必须清理/隔离迟到回复再发下一次请求，否则温度的迟到回复会被当作湿度。本实现的做法是：**每次请求前清空输入缓冲，超时后再次清空**，并在帧读取器中丢弃噪声字节重新对齐。

## 4. 全部样例报文

以下报文中的 CRC 由独立脚本（`artifacts/verification/crc_check.py`，算法独立实现）与程序内 `ModbusCrc` **双实现交叉复算，结果一致**。这些是**开发样例，不是现场抓包**。

### 4.1 请求

| 场景 | 完整报文（十六进制） | 解释 |
|---|---|---|
| 地址 1 读温度 | `01 03 01 00 00 01 85 F6` | 读 `0x0100`，1 个寄存器 |
| 地址 1 读湿度 | `01 03 01 05 00 01 95 F7` | 读 `0x0105`，1 个寄存器 |

### 4.2 正常回复

| 场景 | 完整报文 | 数值 |
|---|---|---|
| 温度 23.5 ℃ | `01 03 02 00 EB F8 0B` | 0x00EB = 235 → 23.5 |
| 温度 0.0 ℃ | `01 03 02 00 00 B8 44` | 0 → 0.0（**0 是有效值**） |
| 温度 −12.3 ℃ | `01 03 02 FF 85 38 17` | 0xFF85 补码 = −123 → −12.3 |
| 湿度 50.0 %RH | `01 03 02 01 F4 B8 53` | 0x01F4 = 500 → 50.0 |

### 4.3 异常回复

| 场景 | 完整报文 | 解释 |
|---|---|---|
| 非法数据地址 | `01 83 02 C0 F1` | 0x83 = 0x03\|0x80；异常码 0x02 |

### 4.4 负例（必须被拒绝）

| 场景 | 完整报文 | 期望拒绝原因 |
|---|---|---|
| CRC 错 | `01 03 02 00 EB F8 0C`（CRC 末字节被改） | CRC 校验失败 |
| 地址错 | `02 03 02 00 EB BC 0B` | 地址不匹配（期望 1，收到 2） |
| 功能码错 | `01 04 02 00 EB F9 7F` | 功能码不匹配（期望 0x03，收到 0x04） |
| 字节数错 | `01 03 04 00 EB 18 0A` | 字节数不匹配（期望 2，收到 4） |
| 截断帧 | `01 03 02 00` | 回复长度不足（收到 4 字节，至少 5 字节） |
| 湿度超量程 | `01 03 02 7F FF D8 34` | 数值 3276.7%RH 高于量程上限 100%RH，按异常值拒绝 |

> 上述负例除 CRC 错与截断外，其 CRC 都按各自内容正确计算，用于确保拒绝原因是**语义校验**而非校验和偶然失效。

## 5. 解析规则（实现约定）

必须是**全部**满足才接受数值：

1. 帧长符合：正常回复 7 字节，异常回复 5 字节；
2. CRC16 低字节先传校验通过；
3. 地址等于期望从站地址；
4. 功能码为 `0x03`（异常帧为 `0x03|0x80`）；
5. 字节数为 `0x02`；
6. 数值落在该指标的量程内，否则按异常值拒绝。

任一不满足 → 拒绝该数值，并**保留明确的质量原因**（超时、CRC 错、地址错、功能码错、字节数错、异常响应、超量程），不伪装成超限。

串口层另行处理：独占打开、分片到达、粘连帧、前置噪声、超时隔离与缓存上界。

## 6. 验证状态

### 已做（模拟/虚拟串口级）

- 协议向量自检（`--self-check`）：CRC 六个标准向量、23.5 ℃ / −12.3 ℃ / 0.0 ℃ / 50.0 %RH 解析、七类负例拒绝、帧读取器的分片/粘帧/噪声/缓存上界，全部通过。
- 虚拟串口端到端回归（`--serial-check COM20 COM21 <模式>`）：
  - `normal`：13 通过 / 0 失败，实测温度帧 `01 03 02 00 EB F8 0B` → 23.5 ℃；湿度帧 `01 03 02 01 F4 B8 53` → 50.0 %RH；读数写入本地库（样本 3 条、分钟 3 条）。
  - `negative`：−12.3 ℃ 正确；`zero`：0.0 ℃ 正确（0 是有效值）。
  - `crc-error` / `exception`：坏帧与异常响应均被拒绝，未冒充读数。
  - `no-response`：不伪造读数。
  - `late`：温度超时后其**迟到回复未被当作湿度**，湿度独立解析为 50.0 %RH；清理迟到帧后再次请求仍正确。
- 交叉验证：程序内 `ModbusCrc` 与独立 Python 实现（`artifacts/verification/crc_check.py`）对全部向量复算一致。

### 未做（实物级，全部待验证）

- 实物传感器的寄存器地址、功能码与回复结构对照；
- 真实温度读数（含负温）与标准仪表对照；
- 温度实际量程、湿度上限（99 还是 100）确认；
- 设备是否使用特殊值（例如 −32768）表示探头故障；
- 最小请求间隔、连续读取限制与副作用；
- 物理接口形式（RS-485/RS-232）、A/B 接线、供电要求、转换器型号与驱动；
- 厂家、固件版本、铭牌信息；
- 24 小时及以上连续运行。

**在上述未做项完成前，本协议只能称为“基于既有实现，待实物验证”，不得声称已通过真机验证。**
